# T23 Properties.load

Implemented: `Properties.load(Reader)` and `Properties.load(InputStream)` (plain methods, JDK's
`Objects.requireNonNull` guards), private `load0(LineReader)` (key/value split, one swallowed separator, virtual
`put` per line), private static `loadConvert(char[],int,int,StringBuilder)` (escapes, `\uxxxx`, malformed-escape
`IllegalArgumentException`), and the private nested `LineReader` (1024-char growing `lineBuf`, 8192-char/byte
source buffers, `readLine` with the JDK's exact refill/continuation/EOF structure). No registration needed:
`Properties` was registered by T22 and `LineReader` is nested.

Left out: `store(Writer,String)`/`store(OutputStream,String)` and `save` (they write the current date, which the
runtime must not read — RULES.md), `list(PrintStream)`/`list(PrintWriter)` (no PrintStream in the runtime),
`loadFromXML`/`storeToXML` (no XML). The JDK methods are `synchronized`; here they are plain, per RULES.md.

Notes: The `readLine` structure was copied from the JDK exactly, including the two quirks the test counts: a
`0` refill is treated like `-1` (`limit <= 0`), and `inOff`/`inLimit` are not updated on an end-of-input return,
so one extra read happens after the end (`"a=1\n"` → 3 reads, `""` → 1, `"#only"` → 2). The JDK's labeled
`commentLoop:` break was rewritten as an equivalent flag loop because no other runtime source uses labels.
`loadConvert` is declared `static` per the task (the JDK's is an instance method); hex digits are checked with
`if`/`else` instead of the JDK's `switch` arrows. `kit check` printed PASS on the first run.
