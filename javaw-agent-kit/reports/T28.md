# T28 AtomicInteger and AtomicLong

Implemented: `java.util.concurrent.atomic.AtomicInteger` and `AtomicLong` in the bundled exception runtime, registered in `BytecodeExceptionRuntime`. Each has both constructors, all plain/opaque/acquire/release/volatile accessors, `getAndSet`, `compareAndSet` plus the five weak variants, `compareAndExchange` plus `Acquire`/`Release`, wrapping `getAndAdd`/`addAndGet`/increment/decrement forms, the four update/accumulate methods using the JDK retry loop, `toString`, and the four `Number` conversions.

Left out: `byteValue()`/`shortValue()` (inherited from the runtime `Number`, as in the JDK), `equals`/`hashCode` (the JDK does not override them), and the JDK-internal `Unsafe`/`VALUE` fields, `serialVersionUID` and `VM_SUPPORTS_LONG_CAS` (they do not exist in the single-threaded runtime).

Notes: The update/accumulate methods needed the JDK retry loop, not `AtomicReferenceArray`'s single-call style — a function that reassigns the atomic must be re-invoked with the new value (`reentrantFunctionsRetryLikeTheJdk`). `kit check T28` printed PASS on the first run.
