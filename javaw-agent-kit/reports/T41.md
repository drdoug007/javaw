# T41 CopyOnWriteArrayList
Implemented: `java.util.concurrent.CopyOnWriteArrayList` (with nested `COWIterator` and `COWSubList`) in the bundled exception runtime: constructors (default, Collection, array), `size`/`isEmpty`, `contains`/`indexOf`/`lastIndexOf` (with and without start index), `get`/`set`/`add`/`remove` (index and object), `removeRange`, `addIfAbsent`/`addAllAbsent`, `containsAll`/`removeAll`/`retainAll`/`clear`, `addAll` (with and without index), `forEach`, `removeIf`, `bulkRemove`, `replaceAll`/`sort` and their range helpers, `toString`/`equals`/`hashCode`, `clone`/`toArray` (both), snapshot `iterator`/`listIterator(int)`, and `subList`.
Left out: serialization (`writeObject`/`readObject`/`serialVersionUID`), the lock (the runtime is single-threaded), the Java 21 `SequencedCollection` members (`getFirst`/`getLast`/`addFirst`/`addLast`/`removeFirst`/`removeLast`/`reversed`), and `stream()`/`spliterator()` overrides (the interface defaults are used).
Notes: this was the fourth attempt on the task; the previous attempts' failures came from leftover-file bugs in the blocked attempt (spurious overridable self-calls in `remove(Object)`/`addIfAbsent`, a `addAll` that dropped existing elements, and a missing `COWSubList.remove(Object)`). `lastIndexOf(e, i)` intentionally keeps the JDK's unclamped `0..i+1` range, so `lastIndexOf(e, 5)` on a 5-element list throws the array's `ArrayIndexOutOfBoundsException`. The full rewrite passed `kit check` on the first run of this attempt.
