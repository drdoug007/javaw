# T70 Instant.parse

Implemented: `java.time.Instant.parse(CharSequence)` in `javaw-bytecode/src/main/resources/exception-runtime/java/time/Instant.java`, plus private helpers `isDigit`, `twoDigits`, `offsetGroup`, `parseError`, `unparsedError`, `resolveError`, `abbreviate`, `isLeap`, `lengthOfMonth`, `epochDay`. Added imports `java.time.format.DateTimeParseException` and `java.util.Objects`. No new classes, so no registration needed; `Instant.java` and `DateTimeParseException.java` were already registered.

Left out: `from(TemporalAccessor)`, `now()`, `atOffset(ZoneOffset)` and all `DateTimeFormatter`/`TemporalAccessor`/`LocalDateTime` types — deliberately unlinked (the test's `rejectsUnusedCall` checks); `parse` is a dedicated hand-written ISO_INSTANT parser instead.

Notes: Check passed on the first attempt. Order of validation is load-bearing: the offset-hours-24..59 resolve error fires during offset parsing (before the date-time value checks, which fire before the unparsed-text check, which fires before the MIN/MAX epoch-second range check). `year % 10_000` is used only for the month/day validity checks; `epochDay` uses the full signed year.
