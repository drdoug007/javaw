# T61 Instant
Implemented: `java/time/Instant` (core subset): `private final long seconds; private final int nanos` normal form with constants `MIN_SECOND`/`MAX_SECOND` and `EPOCH = new Instant(0,0)`, `MIN = ofEpochSecond(MIN_SECOND, 0)`, `MAX = ofEpochSecond(MAX_SECOND, 999_999_999)`; `create` (shared `EPOCH` for `(s|n)==0`, `DateTimeException("Instant exceeds minimum or maximum instant")` out of range); `ofEpochSecond` (both overloads, `Math.addExact` + `floorDiv`/`floorMod` by 10^9), `ofEpochMilli` (floorDiv/floorMod by 1000, never throws); `getEpochSecond`/`getNano`; `plusSeconds`/`plusMillis`/`plusNanos` via private `plus` (`(s|n)==0` returns `this`, addExact carry of `n / 10^9`, result range-checked through `ofEpochSecond`); `minusSeconds`/`minusMillis`/`minusNanos` (`Long.MIN_VALUE` is `plusX(MAX).plusX(1)`); `toEpochMilli` (the JDK's two branches with multiplyExact/addExact, sub-millisecond dropped); `compareTo` (Long.compare then raw `nanos - other.nanos`), `isAfter`/`isBefore`, `equals` (false for null/non-Instant), `hashCode` `((int)(seconds^(seconds>>>32))) + 51*nanos`; `toString()` = ISO_INSTANT with seconds always printed, fraction in groups of three only when `nanos > 0`, the JDK era split (floor division for year 0 and later, truncating division with the `replace`/`insert` fix-ups before it) over a hand-written proleptic Gregorian calendar (`LocalDate.ofEpochDay` with floorDiv/floorMod for negative epoch seconds) and `LocalDate.toString` year padding (`0000`, `-0001`, `+10000`, `-10000`, `MIN` = `-1000000000-01-01T00:00:00Z`, `MAX` = `+1000000000-12-31T23:59:59.999999999Z`).
Left out: everything naming `java.time.temporal`/`Clock`/zones/formatters — `plus/minus(TemporalAmount)` (javac compiles `plus(Duration)` to the TemporalAmount descriptor), `plus/minus(long, TemporalUnit)`, `from(TemporalAccessor)`, `truncatedTo`, `until`, `atZone`, `atOffset`, `get`/`getLong`/`isSupported`/`range`/`with`/`adjustInto`/`query`; `now()`/`now(Clock)` (no clock), `parse(CharSequence)` (no ISO parser); no `implements Temporal`/`TemporalAdjuster`, no serialization proxy, no `LocalDate`/`LocalDateTime`/`ZoneOffset`/`DateTimeFormatter` (calendar arithmetic written by hand).
Notes: First `PASS` on the first `kit check T61`. The year-padding in `appendDateTime` reproduces `LocalDate.toString`'s `append(year +/- 10000)` + `deleteCharAt` trick but offset by the era prefix already in the shared buffer (`deleteCharAt(start)`/`deleteCharAt(start+1)` where `start` is the buffer length before the year); output is identical for every era. The `deleteCharAt` offset matters only in the year-0-and-later branch where `hi > 0` appends `+hi` first.
