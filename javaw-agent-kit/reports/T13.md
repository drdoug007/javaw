# T13 MessageDigest with SHA-256

Implemented: `java.security.GeneralSecurityException`, `NoSuchAlgorithmException`, `DigestException` (four
constructors each); `MessageDigestSpi` (engine contract, default `engineDigest(buf, off, len)`, `clone()`);
`MessageDigest` (`getInstance` backed by the fixed built-in table `javaw.runtime.Digests`, `update`/`digest`/
`reset`, `getAlgorithm`/`getDigestLength`, `isEqual`, `toString`, `clone`); `javaw.runtime.BlockDigest`
(generic `0x80`/zero/length-bit padding engine with big- and little-endian length bytes for T14);
`javaw.runtime.Sha256` (FIPS 180 SHA-256; `ROUND_CONSTS` and `INITIAL_HASHES` copied from the JDK's
`sun.security.provider.SHA2.SHA256`, round logic written by hand).

Left out: `getInstance(String, String)`, `getInstance(String, Provider)`, `getProvider()` (no `Provider`
class), `update(ByteBuffer)` and `engineUpdate(ByteBuffer)` (no `java.nio.ByteBuffer`); SHA-1/MD5/SHA-512
are task T14.

Notes: `kit check` passed on the first attempt. The JDK's `SHA2` compresses from its own byte buffer with
`i2bBig4` helpers; here `BlockDigest` compresses whole blocks straight from the incoming input
(`compress(input, offset)`) so 1000-byte chunks avoid an extra copy. `resetState()` is called at the end of
the `Sha256` constructor, not from `BlockDigest`'s, because the subclass's state array does not exist yet
during the super constructor call.
