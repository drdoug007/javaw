# T78 ByteBuffer float/double accessors, absolute bulk transfers and slice(int, int)

Implemented:
- `ByteBuffer`: `getFloat()`, `getFloat(int)`, `putFloat(float)`, `putFloat(int, float)`, `getDouble()`,
  `getDouble(int)`, `putDouble(double)`, `putDouble(int, double)` — one line each on the T74 int/long
  accessors, using the **raw** conversions (`Float.floatToRawIntBits`/`Double.doubleToRawLongBits`) so NaN
  payloads round-trip bit-exactly.
- `ByteBuffer`: absolute bulk `get(int, byte[], int, int)`, `get(int, byte[])`, `put(int, byte[], int, int)`,
  `put(int, byte[])`, `put(int, ByteBuffer, int, int)` — limit check first, then the array/source check
  (`src.limit()` for buffer sources), read-only first for the puts, `System.arraycopy` (so `src == this` and
  overlapping ranges work), positions and marks untouched, return `this`.
- `ByteBuffer.slice(int, int)` (abstract) / `HeapByteBuffer.slice(int, int)`: range check against the limit,
  then a view with offset `offset + index`, position 0, limit = capacity = length, mark -1, same read-only
  flag, big-endian.
- Made `ByteBuffer.checkRange` package-private so `HeapByteBuffer.slice(int, int)` reuses it (its message
  matches the JDK `Objects.checkFromIndexSize` text).

Left out: view buffers (`asFloatBuffer`, `asDoubleBuffer`, ...), `mismatch`, `alignmentOffset`,
`alignedSlice`, and direct buffers — all rejected before WAT generation, per the task.

Notes: passed on the first `kit check` attempt. The relative bulk `put(ByteBuffer)` keeps its
`src == this` rejection (T74 behaviour); only the absolute `put(int, ByteBuffer, int, int)` allows it, as
in the JDK.
