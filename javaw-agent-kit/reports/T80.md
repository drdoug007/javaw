# T80 Month and DayOfWeek
Implemented: `java.time.Month` (12 constants, `of(int)`, `getValue()`, `plus/minus(long)`, `length(boolean)`, `minLength()`, `maxLength()`, `firstDayOfYear(boolean)`, `firstMonthOfQuarter()`) and `java.time.DayOfWeek` (7 constants, `of(int)`, `getValue()`, `plus/minus(long)`) in the bundled exception runtime; both registered in `BytecodeExceptionRuntime.java` via `kit register`.
Left out: `TemporalAccessor`/`TemporalAdjuster` and all of their members (`from`, `get`, `getLong`, `range`, `isSupported`, `query`, `adjustInto`), plus `getDisplayName(TextStyle, Locale)` — those types (`java.time.temporal.TemporalAccessor`, `java.time.format.TextStyle`, `ValueRange`, etc.) are not in the runtime, and the test requires the calls to stay unlinked.
Notes: `minus(long)` takes the remainder before negating (`plus(-(amount % N))`) so `Long.MIN_VALUE` does not overflow. `firstDayOfYear` adds the leap day only from `MARCH` on. No `switch` on the enum in the runtime sources (a `switch` in the test fixture's application code compiles fine).
