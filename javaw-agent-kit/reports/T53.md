# T53 Timed tryLock, offer and poll

Implemented: `Lock.tryLock(long, TimeUnit)`, `ReentrantLock.tryLock(long, TimeUnit)`,
`ReentrantReadWriteLock.ReadLock.tryLock(long, TimeUnit)` and `WriteLock.tryLock(long, TimeUnit)`,
`BlockingQueue.offer(E, long, TimeUnit)` / `poll(long, TimeUnit)`, and
`LinkedBlockingQueue.offer(E, long, TimeUnit)` / `poll(long, TimeUnit)`. Each first evaluates
`unit.toNanos(timeout)` (null unit -> NPE, state unchanged; for `offer` the null-element check comes first)
and then behaves exactly like its untimed sibling: tryLock true with the usual hold-count guards,
WriteLock false on the read-then-write upgrade case, offer false when full, poll null when empty.

Left out: `newCondition`/`Condition` and queue inspection/serialization members (`getQueueLength`,
`hasQueuedThreads`, `LinkedBlockingQueue.writeObject`) remain unlinked per the task; `TimeUnit.sleep` and
any waiting behaviour were not added.

Notes: `kit check` passed on the first attempt. All five files were already registered; only
`import java.util.concurrent.TimeUnit` was needed in the two `locks` package files and the new `Lock`
interface method.
