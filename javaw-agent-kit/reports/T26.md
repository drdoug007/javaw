# T26 StringWriter and CharArrayWriter

Implemented: `java/io/StringWriter.java` (final `StringBuffer buf`, both constructors assigning
`lock = buf`, `write(int)`/`write(char[],int,int)` with the inline JDK range check and `len == 0`
early return, `write(String)`/`write(String,int,int)` delegating to `buf.append`, covariant
`append(CharSequence)`/`append(char)`/`append(csq,start,end)` calling the overridable write/append
forms and returning `this`, live `getBuffer()`, no-op `flush()`/`close()`) and
`java/io/CharArrayWriter.java` (protected `buf`/`count`, `this(32)` default constructor, the
`Math.max(buf.length << 1, newcount)` growth rule in every write, `writeTo(Writer)` as one internal-array
call, `reset()`, `toCharArray()`, `size()`, `toString()`, covariant appends, no-op `flush()`/`close()`).
Both registered; `docs/bytecode-string-writer.md` added.

Left out: nothing else exists on these JDK 21 classes. No `synchronized (lock)` blocks per RULES.md;
`write(char[])`/`write(String)` intentionally not overridden so the inherited `Writer` forms produce the
JDK call patterns and `NullPointerException`s.

Notes: first check: PASS. Kept the JDK's differing exception types for the same bad
`write(String,int,int)` range (plain `IndexOutOfBoundsException` from `StringBuffer` in
`StringWriter`, `StringIndexOutOfBoundsException` from `getChars` after the pre-growth in
`CharArrayWriter`) and wrote the range check inline in each class rather than reusing the package-private
`Reader`/`InputStream` helpers.
