# T42 ConcurrentLinkedQueue

Implemented: `java.util.concurrent.ConcurrentLinkedQueue` (new file under
`exception-runtime/java/util/concurrent/`, registered by `kit register`) with `Node`, the sentinel `head` and
`tail`, both constructors, `offer`, `poll`, `peek`, `isEmpty`, `size`, `contains`, `remove(Object)`,
`addAll`, `toString`, `toArray`, `toArray(T[])`, `iterator`, `forEach`, `removeIf`, `removeAll`, `retainAll`,
`clear`, `bulkRemove` and the non-static inner `Itr`. `add`, `remove()`, `element()` and `containsAll` are
inherited from `AbstractQueue`/`AbstractCollection` as-is.

Left out: `writeObject`/`readObject` (serialization classes are not in the runtime; the test checks
`writeObject` stays unlinked), `spliterator`/`CLQSpliterator` (inherited `Collection.spliterator()` default
is enough), and all JDK CAS/`VarHandle` internals (`casItem`, `updateHead`, `succ`, self-linked nodes,
`MAX_HOPS`) — replaced by direct single-threaded node walks. No `synchronized`, no `volatile`.

Notes: kit check passed on the first run. Followed the task's `bulkRemove` walk exactly (`q = p.next` read
first; unlink a dead node with a successor, else advance `pred`). `isEmpty` and `toArray` walk the nodes
themselves rather than calling the overridable `peek()`/`size()` — the `subclassCalls` fixture
(`Spy`) confirms no `peek:`/`size:`/`iterator` entries are logged for them. `toString` throws
`NullPointerException` for an item whose `toString()` returns null, matching the JDK rather than
`StringBuilder.append`'s `"null"` printing.
