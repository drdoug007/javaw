# T34 OutputStreamWriter

Implemented: `java.io.OutputStreamWriter` (three constructors, `getEncoding`, `write(int)`, `write(char[], int, int)`,
`write(String, int, int)`, `append(CharSequence)`, `flush`, `close`, and the private `ensureOpen`/`writeString`/
`writeChars`/`grow`/`put`/`putUnit`/`flushBytes` helpers encoding UTF-8, ISO-8859-1, US-ASCII, UTF-16BE, UTF-16LE and
UTF-16 with a 512-to-8192-byte buffer, a high surrogate kept between writes, and the UTF-16 byte order mark). Added
`PrintWriter(OutputStream)` and `PrintWriter(OutputStream, boolean)` to the existing `PrintWriter`.

Left out: `OutputStreamWriter(OutputStream, CharsetEncoder)` (no `CharsetEncoder` in the runtime), the
package-private `flushBuffer()` and the JDK's private lock (single-threaded contract), and
`PrintWriter(OutputStream, boolean, Charset)` (checked by the test as unlinked). No `BufferedWriter` under
`PrintWriter(OutputStream)`; see the docs for the two resulting known differences.

Notes: `kit check` printed PASS on the first run (138 new lines). The `Spy` trace in the task (`c(a)a(0,2)...`)
works out exactly: `write(int)` and `append(char)` reach the private `writeChars` without a virtual dispatch to
`write(char[], int, int)`, so no `a(0,1)` entries appear.
