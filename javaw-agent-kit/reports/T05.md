# T05 ArrayDeque

Implemented: `java.util.ArrayDeque<E>` (resizable ring buffer, rejects null) registered in
`BytecodeExceptionRuntime`. All task members: the three constructors, `addFirst`, `addLast`, `offerFirst`,
`offerLast`, `removeFirst`, `removeLast`, `pollFirst`, `pollLast`, `getFirst`, `getLast`, `peekFirst`,
`peekLast`, `removeFirstOccurrence`, `removeLastOccurrence`, `add`, `offer`, `remove()`, `poll`, `element`,
`peek`, `push`, `pop`, `addAll`, `iterator()`, `descendingIterator()`, `size`, `isEmpty`, `contains`,
`remove(Object)`, `clear`, `toArray()`, covariant `ArrayDeque<E> clone()`, plus private `Itr`,
`DescendingItr`, `delete(int)` and `grow()`.

Left out: `reversed()` (JDK 21; the test verifies admission rejects it before WAT generation), `spliterator()`,
serialization hooks (only the `Serializable` marker and `serialVersionUID`), `equals`/`hashCode` overrides (the
JDK uses identity). `toArray(T[])`, `containsAll`, `removeAll`, `retainAll`, `toString` are inherited from the
runtime `AbstractCollection`; `removeIf`/`forEach` come from interface defaults.

Notes: The previously blocked attempt had four failing fixtures, all caused by one dead growth check:
`ensureCapacity(size)` required `size > elements.length`, so a full buffer silently overwrote elements and
`slot(i)` went out of bounds (Wasm traps). Replacing it with an unconditional `grow()` — `length * 2 + 2`, copy
in logical order, `head = 0` — fixed every failure. One cosmetic leftover: a dangling orphan javadoc block sits
above `iterator()` (lines 503-507); it is a plain comment with no behavioural effect.
