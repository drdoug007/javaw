# T12 HexFormat
Implemented: `java/util/HexFormat.java` (`package java.util;`, `public final class HexFormat`) with the private
fields `String delimiter, prefix, suffix` and `boolean upperCase`, one private constructor, and the full member
set: `of()`, `ofDelimiter(String)`, `withDelimiter/withPrefix/withSuffix/withUpperCase/withLowerCase`, the four
accessors `delimiter()/prefix()/suffix()/isUpperCase()`, `formatHex(byte[])` / `formatHex(byte[],int,int)`,
`parseHex(CharSequence)` / `parseHex(CharSequence,int,int)`, `toLowHexDigit(int)` / `toHighHexDigit(int)`,
`toHexDigits(byte/char/short/int/long)` plus `toHexDigits(long,int)`, static `isHexDigit(int)` /
`fromHexDigit(int)` / `fromHexDigits(CharSequence[,int,int])` / `fromHexDigitsToLong(CharSequence[,int,int])`,
and `equals/hashCode/toString`. Registered via `kit register java/util/HexFormat.java`.

Left out: `formatHex(Appendable, byte[])`, `formatHex(Appendable, byte[], int, int)`, `toHexDigits(Appendable,
byte)` and `parseHex(char[], int, int)` — they need `java.io.UncheckedIOException` and `java.nio.CharBuffer`,
neither in the runtime; `leavesAppendableAndCharArrayOverloadsUnlinked` confirms they stay rejected.

Notes: first check failed on a javac error — I called a private two-arg `fromHexDigits(CharSequence,int)` helper
that does not exist in the public surface, so all three call sites were changed to the public
`fromHexDigits(string, offset, offset + 2)` form. Second check failed on `delimited()`: I built the between-bytes
text as `suffix + delimiter + prefix` (JDK style) but my loop already appends `prefix + 2 digits + suffix` for
every byte, so the suffix was doubled (`0x0ahh`). The delimiter between bytes is just `delimiter`; after that the
third check passed, matching the JVM on every fixture. `checkRange` replicates `Objects.checkFromToIndex` (absent
from the runtime) with the exact `Range [from, to) out of bounds for length L` message.
