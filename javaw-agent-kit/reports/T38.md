# T38 EnumMap

Implemented: `java/util/EnumMap.java` — the whole public `Map` surface over an `Object[]` indexed by
`ordinal()`, with the `NULL` stand-in for `null` values (`maskNull`/`unmaskNull`). The three constructors
(`Class` via `getEnumConstants()`; `EnumMap` clone; `Map` with the `Specified map is empty` message and
`getDeclaringClass()`, never `getClass()`, so constants with bodies give the declaring enum). `size`/`get`/
`put`/`remove`/`containsKey`/`containsValue`/`clear` (same-array `Arrays.fill`), `putAll` with the
same-key-type fast path (a different `em.keyType` returns when the source is empty, else
`ClassCastException(em.keyType + " != " + keyType)`, `class Op != class Color`) and `super.putAll`
otherwise (`class Op$2 != class Color` per entry, `putAll(null)` NPE), `isValidKey` for queries and
`typeCheck` with its `class X != class Y` message for `put`, the `containsMapping`/`removeMapping` helpers,
the cached live `KeySet`/`Values`/`EntrySet` views (`KeySet.remove` compares the map `size` before and
after; `Values.remove` clears the first slot equal to `maskNull(o)`; `EntrySet` methods go through the
mapping helpers and reject non-`Entry` arguments), the `EnumMapIterator`/`KeyIterator`/`ValueIterator`/
`EntryIterator` (live-array `hasNext` skipping `null` slots, `NoSuchElementException`, messageless
`IllegalStateException` remove rules, `EntryIterator.remove()` copying the entry's index before
`super.remove()`), and the live `MapEntry` (`Entry was removed` `IllegalStateException` once the iterator
removes it, `setValue` writes through without touching `size`). `equals` (raw slots for another `EnumMap`
with the different-key-type-iff-empty rule; `Map` form requiring `get == null && containsKey` for null
values), `hashCode` (sum of `keyUniverse[i].hashCode() ^ vals[i].hashCode()` over filled slots,
`NULL.hashCode()` 0), `clone()` (`vals.clone()` plus resetting all three view caches, `InternalError`
wrap) and inherited `toString`/`isEmpty`/`getOrDefault`/`putIfAbsent`/`merge`. Registered via
`kit register java/util/EnumMap.java`.

Left out: serialization (`writeObject`, `readObject`, `serialVersionUID`) — the test checks
`EnumMap.writeObject` stays unlinked. `EntrySet.toArray`/`toArray(T[])` are not overridden: the inherited
`AbstractCollection` versions return the live `MapEntry` objects where the JDK returns
`AbstractMap.SimpleEntry` copies (documented known difference; fixtures never call them). `isEmpty`,
`toString`, `getOrDefault`, `putIfAbsent`, `merge` and the other `Map`/`AbstractMap` defaults are inherited
and not overridden. `AbstractMap`, `Enum`, `Class` and all other runtime files untouched.

Notes: the starting tree already contained a complete `EnumMap.java` — the kit's `start --resume` had
reapplied the previous blocked attempt's saved patch, which covered only the runtime file; the registration
in `BytecodeExceptionRuntime.java` had been restored away by the earlier block. I verified every member of
the file against the task spec, ran `kit register`, and `kit check T38` passed on the first run (all seven
test methods, including `leavesOutSerialization`).
