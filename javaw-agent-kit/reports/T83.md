# T83 java.lang.ref references and ReferenceQueue

Implemented: `java/lang/ref/Reference.java` (abstract, package-private constructors; `get`, `final refersTo`
reading the `referent` field with `==`, `clear`, deprecated `isEnqueued`, `enqueue` which nulls the field
directly and then calls `queue.enqueue(this)`), `ReferenceQueue.java` (`Null` subclass, `NULL`/`ENQUEUED`
sentinels, LIFO `enqueue`/`poll` at the head with a self-loop end, `remove(timeout)` with the JDK
"Negative timeout value" message, `remove()` throwing `IllegalStateException` on an empty queue),
`WeakReference.java` (both constructors), `SoftReference.java` (both constructors, `get` override),
`PhantomReference.java` (queue constructor, `get` returns `null`).

Left out: `Cleaner` (needs a daemon thread; the test checks it stays unlinked), `reachabilityFence` (not
referenced; the test checks it stays unlinked), `FinalReference`/`Finalizer`/the protected `clone()` that
throws, the reference-handler thread and `waitForReferenceProcessing`, `ReferenceQueue.forEach`, the queue's
lock/condition and `queueLength`, `SoftReference`'s LRU `clock`/`timestamp`, native `refersTo0`/`clear0`. No
`equals`/`hashCode`/`toString` overrides, no `Serializable`/`Cloneable`.

Notes: passed `kit check` on the first attempt. The calibration traps the task lists are covered by design:
`enqueue()` nulls the field directly (a `Spy` subclass's `clear()` override is never called, and the referent
is cleared even when `queue.enqueue` returns `false`), `refersTo` reads the field (so `PhantomReference`
answers `true` and `get` never appears in the spy log), the queue is LIFO (push/poll at the head), and
`poll()` resets `r.queue` to `NULL` (not `null`) so a second `enqueue()` returns `false` instead of throwing.
