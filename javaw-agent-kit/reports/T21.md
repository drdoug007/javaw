# T21 Dictionary and Hashtable

Implemented: `java.util.Dictionary<K,V>` (abstract, seven abstract members, no other members) and
`java.util.Hashtable<K,V> extends Dictionary` implementing `Map`, `Cloneable`, `java.io.Serializable`
(without `AbstractMap`): the four constructors, size/isEmpty/keys/elements/contains/containsValue/
containsKey/get/put/remove/putAll/clear/clone/toString/equals/hashCode, cached KeySet/ValueCollection/
EntrySet views, the overridden Map defaults (getOrDefault, forEach, replaceAll, putIfAbsent, remove(k,v),
both replaces, computeIfAbsent), private `indexFor`/`find`/`addEntry`/`grow` helpers, the private static
`Entry<K,V>` (with recursive `copy()` for clone) and the private inner `Enumerator<T>` shared by
enumerations and view iterators, including the `count == 0` empty-enumeration/empty-iterator special case.

Left out: `rehash()` (named `grow()`; `leavesOutRehash` verifies it stays unlinked), `compute`/
`computeIfPresent`/`merge` (inherited Map defaults), serialization hooks, the `Hashtable(Void)`
constructor, the negative-loadFactor "hash in progress" trick, spliterators.

Notes: the first run passed layout, growth and order on the first try; the only Wasm-versus-JVM
divergence was `toString`, which I initially wrote as "separator after an entry that has a `next` in its
own bucket chain". That omits the `", "` at bucket-chain boundaries; the JDK prints a separator between
every consecutive pair in iteration order (the `constructors` fixture with six singleton buckets proves
it). Changed to a first-entry flag and it passed on the next check.
