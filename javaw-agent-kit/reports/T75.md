# T75 Callable, Future and FutureTask

Implemented: `java.util.concurrent.Callable` (@FunctionalInterface), `Future` (the five abstract members
only), `RunnableFuture`, `FutureTask` (both constructors, `run` with the `state != NEW || running`
re-entrancy guard, virtual `set`/`setException` called from `run` with `set(result)` outside the
`try/catch (Throwable)`, `cancel`, `isCancelled`, `isDone`, `get`, timed `get`, `done`, the JDK-21 `toString`
suffixes), `ExecutionException` (protected no-arg/String + public (String, Throwable)/(Throwable)),
`CancellationException` (extends IllegalStateException), `TimeoutException`. All seven registered with
`kit register`; `docs/bytecode-future-task.md` created.

Left out: `FutureTask.runAndReset`, the JDK 19+ `resultNow`/`exceptionNow`/`state` and `Future.State`
(fixtures compile for Java 17), `Executors`/`ExecutorService`/`CompletableFuture`/`ScheduledFuture`/`Delayed`
(not this task; the `(Runnable, V)` constructor uses a private static `Callable<T>` adapter instead of
`Executors.callable`), the JDK internals (WaitNode/awaitDone/VarHandles/LockSupport/runner thread/interrupts)
and `volatile`/`synchronized` (single-threaded contract).

Notes: passed on the first check. Two behavioural details mattered and are covered in the task call-outs:
`cancel(true)` stores the `INTERRUPTED` state (still `isCancelled() == true`, still `[Cancelled]`), and
`get(timeout, unit)` checks `unit == null` before the done check, so a done task with a null unit still
throws `NullPointerException`.
