# T31 String range failure messages

Implemented: JDK 21 exception messages for `String`, `StringBuilder` and `StringBuffer` index/range failures.
`String` gained package-private static helpers `checkIndex`, `checkOffset`, `checkBoundsBeginEnd`,
`checkBoundsOffCount` and `rangeMessage`; `charAt`, `codePointBefore`, `substring(int,int)`, `getChars`, the
deprecated `getBytes(int,int,byte[],int)`, the `char[]`/`byte[]`/`int[]` constructors, `codePointCount` and
`repeat` now throw through them (the `int[]` constructor's range failure changed to
`StringIndexOutOfBoundsException`, its invalid code point `IllegalArgumentException` now carries the code
point, `repeat` now says `count is negative: <count>`). `StringBuilder` calls the `String` helpers
(`charAt`, `setCharAt`, `deleteCharAt`, `delete`, `replace`, `substring`, `getChars`, all `insert`
overloads; `appendCodePoint` throws its own `IllegalArgumentException` inline), and `append(CharSequence,int,int)` / `append(char[],int,int)` /
`insertSequence` use the plain-`IndexOutOfBoundsException` range message. `StringIndexOutOfBoundsException(int)`
now formats `String index out of range: <n>`; `TextCharsets.decode(byte[],int,int,int)` uses the offset/count
range message.

Left out: `NullPointerException` messages and `new StringBuilder(-1)` are out of scope per the task; writers
were not edited (their failures come from the fixed `StringBuilder`/`String` paths).

Notes: `kit check T31` passed on the first attempt. The JDK 21 formats were verified against the pinned JDK 21
sources (`Preconditions` formatters, `AbstractStringBuilder`'s clamp-then-check order, `String.checkIndex` /
`checkOffset`) before implementing; the int-sum overflow cases (e.g. `Range [1, -2147483648)`) and the recorded
`length()`/`charAt` call order on `CharSequence` arguments matched the JVM fixtures on the first run.

Review fixes: the docs' check-order bullet now says `String.getChars` reports a bad destination as
`StringIndexOutOfBoundsException` (offset/count form) and only `StringBuilder.getChars` uses the plain
`IndexOutOfBoundsException`; the report no longer claims `appendCodePoint` goes through the `String` helpers.
`String.repeat` now throws `OutOfMemoryError("Required length exceeds implementation limit")` on length overflow
(it had no message), using the JDK 21 byte-length limit (twice the char length when any char is above `0xFF`).
Verified with a renamed-package copy of the check against JDK 21 `String.repeat` (20000 inputs, no differences)
and the new `repeatLengthLimit` JVM/Wasm case.
