# T18 InputStream and ByteArrayInputStream

Implemented: `java.io.EOFException` (two constructors), `java.io.InputStream` (abstract base with the
default `read`/`readNBytes`/`skip`/`skipNBytes`/`transferTo` built on `read()`, the package-private
`checkFromIndexSize` bounds helper, and a fresh anonymous `nullInputStream()` per call) and
`java.io.ByteArrayInputStream` (shared buffer, protected `buf`/`pos`/`mark`/`count`, clamping
constructor, `read`/`readAllBytes`/`readNBytes`/`skip`/`transferTo`/mark-reset overrides; `read(byte[])`,
`readNBytes(int)` and `skipNBytes(long)` inherited).

Left out: JDK `synchronized` methods and the `volatile` `closed` flag (single-threaded runtime, per
RULES.md); `readNBytes(int)` uses a growing buffer instead of the JDK's 16384-byte chunks and join
(observably identical); `ByteArrayInputStream` constructors keep the JDK's lack of range checks.

Notes: The runtime sources from the previously blocked attempt were still in the working tree and were
correct — the only missing step was registration (`kit register` for all three classes). `kit check`
passed on the first run after registering.
