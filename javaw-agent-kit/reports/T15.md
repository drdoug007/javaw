# T15 SecretKeySpec and Mac (HMAC)

Implemented: `java.security.Key`, `KeyException`, `InvalidKeyException`, `spec.KeySpec`,
`javax.security.auth.Destroyable`, `DestroyFailedException`, `javax.crypto.SecretKey`, `spec.SecretKeySpec`
(two constructors, `getAlgorithm`/`getFormat`/`getEncoded`, `equals`, JDK 21 `hashCode`) and `javax.crypto.Mac`
(private constructor; `getInstance`, `getAlgorithm`, `getMacLength`, `init`, `update` x3, `doFinal` x2, `reset`
over the built-in digests via `javaw.runtime.Digests`, 64/128-byte blocks). Registered all nine sources.

Left out: `Mac.getInstance(String, String)`/`(String, Provider)`, `getProvider()`,
`init(Key, AlgorithmParameterSpec)`, `update(ByteBuffer)`, `doFinal(byte[], int)` (needs `ShortBufferException`),
`clone()` and `MacSpi` — the test's admission checks cover the first three.

Notes: `kit check` passed on the first attempt. `SecretKeySpec` inherits the `Destroyable` defaults, so
`destroy()` throws `DestroyFailedException` with a null message rather than zeroing the key, as the task spec
says the JDK does. A key longer than the block is hashed before the pads are built (RFC 4231 case 6); a key of
exactly the block size is not.
