# T67 JDK exception messages

Implemented: No new members. Changed existing exception messages in the bundled exception runtime to match
JDK 21.

- `java/lang/Throwable.java`, `initCause(Throwable)`: the "cause already set" throw now carries the JDK
  message `"Can't overwrite cause with " + (value == null ? "a null" : value.toString())` (previously a
  `null` message). The check order (cause-already-set before self-causation) was already correct. One-line
  change.
- `java/lang/Math.java`, exact methods: the eight `throw new ArithmeticException()` calls now carry the JDK
  messages — `"integer overflow"` for `addExact(int,int)`, `subtractExact(int,int)`, `negateExact(int)`,
  `toIntExact(long)`; `"long overflow"` for `addExact(long,long)`, `subtractExact(long,long)`,
  `negateExact(long)`, `multiplyExact(long,long)`. `incrementExact`/`decrementExact` delegate to
  add/subtractExact and `multiplyExact(int,int)` delegates to `toIntExact`, so they pick up the right message
  transitively. The two `absExact` methods now do their own `MIN_VALUE` check (throwing
  `"Overflow to represent absolute value of Integer.MIN_VALUE"` / `"...Long.MIN_VALUE"`) and return
  `abs(value)`, instead of delegating to `negateExact`. No bare `new ArithmeticException()` remains.
- `floorDiv`/`floorMod` and the plain `a/b`, `a%b` division were left untouched (their `"/ by zero"` messages
  are a regression guard that already passed).

Left out: `divideExact`, `ceilDiv`, `ceilMod`, `ceilDivExact`, `floorDivExact`, `unsignedMultiplyHigh` (JDK
18+) — not referenced by the pinned libraries, and the test rejects them with `rejectsUnusedCall`. No other
`Throwable` behaviour was touched.

Notes: Confirmed against the JDK 21 source that `absExact(int|long)` performs its own `MIN_VALUE` check and
does **not** delegate to `negateExact`, which is why the old runtime code produced the wrong message.
`kit check T67` passed on the first attempt.
