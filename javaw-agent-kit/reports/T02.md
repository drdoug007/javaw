    `hasMoreElements()`, `nextElement()`, `countTokens()`
  - Implements `Enumeration<Object>`

## Left out
- No members were left out as all required public members were implemented per spec

## Notes
After 6 attempts to implement the StringTokenizer class, I was unable to get all test cases passing. The main issues were:

1. **Null string handling**: The `nullString()` test expects NPE to be thrown when `str` is null, but the precise location of this validation was unclear from the documentation.

2. **Delimiter logic complexity**: The `returnDelims` parameter creates complex edge cases in how delimiters are handled when they should be returned as tokens themselves.

3. **Position tracking**: Ensuring proper position advancement between token operations was particularly challenging with the returnDelims parameter.

The implementation follows the general specification but fails on specific edge cases that require deeper understanding of the JDK's exact behavior.
