# T74 java.nio.Buffer and the heap ByteBuffer core

Implemented: `java.nio.Buffer` (mark/position/limit/capacity state, JDK exception messages, the
`nextGetIndex`/`nextPutIndex`/`checkIndex` helpers), `java.nio.ByteBuffer` (allocate/wrap, relative and absolute
byte access, bulk transfers with the JDK range-check message, `put(ByteBuffer)` via a temporary copy,
short/char/int/long access in both byte orders, order()/order(bo) with `order(null)` = little-endian, covariant
Buffer-returning overrides, toString/hashCode/equals/compareTo), package-private `HeapByteBuffer`
(get/put/slice/duplicate/asReadOnlyBuffer/compact/one flag for read-only), and the four exceptions
`BufferUnderflowException`, `BufferOverflowException`, `InvalidMarkException`, `ReadOnlyBufferException`.
All seven registered with `kit register`.

Left out: direct and mapped buffers (`allocateDirect` stays unlinked), view buffers and float/double accessors
(`asLongBuffer`, `getFloat`), the JDK 13+ absolute bulk members (`slice(int, int)`, `put(int, ...)`), and
`mismatch`/`alignmentOffset`/`alignedSlice` — later tasks. `isDirect()` always returns false.

Notes: one javac typo in the first version (missing `return this;` in `Buffer.flip()`) broke the whole runtime
build; after the fix all seven test methods passed on the next check, with the only behavioural decisions the
task call-outs flagged: absolute indexes checked against the limit (not capacity), views reset to big-endian,
`compareTo` returning the signed byte difference `x - y` rather than -1/0/1, and `put(ByteBuffer)` copying
through a temp array for overlapping shared-array ranges.
