# T47 ConcurrentHashMap

Implemented: `java.util.concurrent.ConcurrentHashMap` with the prescribed storage (16-slot chained table, `spread`,
tail insertion, doubling at 3/4), the five constructors, `putVal`/`replaceNode`/`findNode` helpers, queries,
writes, the four `ConcurrentMap` methods, `computeIfAbsent`/`computeIfPresent`/`compute`/`merge`,
`equals`/`hashCode`/`toString`, the cached `KeySetView`, values and entry-set views (`CollectionView` base),
`BaseIterator` with key/value/entry iterators, and `MapEntry`. Registered with `kit register`.

Left out: the T48 members (`newKeySet`, `keySet(V)`, `getMappedValue`, `keys`, `elements`, `mappingCount`,
`contains`, `getOrDefault`/`forEach`/`replaceAll` overrides, view `forEach`/`removeIf`), the parallel bulk
operations and serialization, as the task requires.

Notes: Finished by Claude (Opus) after four local-model sessions were blocked. Every earlier check failed all ten
tests for one reason: the runtime did not compile (`non-static type variable K1 cannot be referenced from a
static context` in iterators nested inside the views), so no behaviour test ever ran; the last session then timed
out after 240 minutes without another check. The class was rewritten from the spec with the iterators as direct
static members of `ConcurrentHashMap` (the shape in the task hint) and passed on the first check. Internal paths
(`toString`, `hashCode`, `containsValue`, the compute family, `putAll`) walk the table or use the non-overridable
helpers, so the `Spy` fixture sees only the self-calls the JDK makes.
