# T11 BitSet bulk operations
Implemented: in the existing `java/util/BitSet.java` — `and`, `or`, `xor`, `andNot`, `intersects`, `equals(Object)`, `hashCode`, `clone`, `toLongArray`, `toByteArray`, `valueOf(long[])`, `valueOf(byte[])`; plus the `private BitSet(long[] words)` constructor and a `private transient boolean sizeIsSticky` flag (set in `BitSet(int)`, cleared in `ensureWords`'s growth branch, consulted by `clone` before `super.clone()`). No registration edit: T10 already registered `"BitSet"`.
Left out: `valueOf(java.nio.ByteBuffer)` and `valueOf(java.nio.LongBuffer)` — the buffer classes are not in the runtime; both stay rejected by `rejectsUnlinkedMembers`. `get(int,int)` and `stream()` remain absent as T10's test requires.
Notes: first check passed. `or`/`xor` compute `common` before growing and set `wordsInUse = set.wordsInUse` after `ensureWords(set.wordsInUse - 1)`, matching T10's `max(2 * words.length, set.wordsInUse)` rule exactly (`of(70).or(of(130))` gives size 256). Only `and` and `or` take the `set == this` shortcut, so `a.xor(a)` and `a.andNot(a)` clear `a`. `clone` trims the original's array when not sticky before cloning, then deep-copies `words`, so both original and copy can shrink through a clone.
