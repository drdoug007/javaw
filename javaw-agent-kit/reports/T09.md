# T09 synchronized collections
Implemented: `Collections.synchronizedCollection/Set/List/Map` factories in `java/util/Collections.java`; new package-private `java/util/SynchronizedViews.java` with `CollectionView`, `SetView`, `ListView`, `RandomListView` and `MapView` — monitor-free delegating views that forward every `Collection`/`List`/`Map` method (including the interface defaults `forEach`, `removeIf`, `spliterator`, `stream`, `replaceAll`, `sort` and all `Map` default methods) straight to the backing collection. Registered via `kit register`.
Left out: `synchronizedSortedSet/Map`, `synchronizedNavigableSet/Map` (stays rejected; `leavesOutSortedVariants` and `BytecodeSortedCollectionsTest` check it) and the package-private `(…, Object mutex)` overloads — per the task's "Members to leave out".
Notes: `kit check T09` printed PASS on the first attempt. `CollectionView` deliberately does not override `equals`/`hashCode` (identity), while `SetView`/`ListView`/`MapView` delegate to the backing collection; `ListView.subList` reuses the single `SynchronizedViews.list` factory so `RandomAccess` propagates through `subList` exactly like the JDK.
