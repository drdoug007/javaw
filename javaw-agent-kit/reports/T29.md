# T29 AtomicBoolean and AtomicReference

Implemented: `java.util.concurrent.atomic.AtomicBoolean` and `java.util.concurrent.atomic.AtomicReference` in the
exception runtime, registered in `BytecodeExceptionRuntime.java` (via `kit register`), and
`docs/bytecode-atomic-boolean-reference.md`. Both classes carry the complete Java 17 public API: both
constructors, `get`/`set`/`lazySet`, `getAndSet`, `compareAndSet`, all five `weakCompareAndSet*`, all three
`compareAndExchange*`, the plain/opaque/acquire/release access modes, and `toString`; `AtomicReference` also has
`getAndUpdate`/`updateAndGet`/`getAndAccumulate`/`accumulateAndGet`. Both implement `java.io.Serializable` with
`Object`'s `equals`/`hashCode`.

Left out: the JDK's private `serialVersionUID`, the `VarHandle VALUE` field and its static initializer (no
`VarHandle` in the runtime). No other members are part of the public API.

Notes: single-threaded contract copied from `AtomicReferenceArray` — plain field, identity compares, no spurious
CAS failure. The four function methods use the JDK's compare-and-set retry loop (not `AtomicReferenceArray`'s
single-shot bodies), which is observable when a function mutates the reference it updates. Non-final members are
exactly `AtomicBoolean.weakCompareAndSet`, `AtomicBoolean.weakCompareAndSetPlain`, and both `toString` methods;
no internal method calls one of them. Kit check PASSED on the first run.
