# T07 Vector

Implemented: `java.util.EmptyStackException` (no-arg constructor only) and a monitor-free
`java.util.Vector<E>` under `javaw-bytecode/src/main/resources/exception-runtime/java/util/`, both
registered in `BytecodeExceptionRuntime.java` via `kit register`. Vector extends `AbstractList<E>`
and implements `List<E>, RandomAccess, Cloneable, java.io.Serializable` with the constructors
(default 10, sized, from-`Collection`), `size`/`isEmpty`/`capacity`, the legacy members
(`addElement`, `elementAt`, `firstElement`, `lastElement`, `insertElementAt`, `removeElementAt`,
`removeElement`, `removeAllElements`, `copyInto`, `elements`, `indexOf`/`lastIndexOf` with from
index) and the `List` members (`get`, `set`, `add` both forms, `remove` both forms, `addAll` both
forms, `clear`, `contains` inherited, `toArray` both forms, `clone` via `super.clone()`). A single
private `grow(int minimum)` helper does the `max(old*2, needed)` growth.

Left out: `setSize(int)` and the `Vector(int,int)` constructor (the test requires both be rejected
before WAT generation); `trimToSize`, `ensureCapacity`, `removeRange`, `spliterator` overrides and
serialization hooks are not needed. All JDK `synchronized` modifiers were dropped in favour of the
single-threaded contract; no `setSize`-style backing is provided.

Notes: `addAll(int, Collection)` moved the tail to `index + numMoved` on the first draft (a slip
from `ArrayList`'s different growth arithmetic), corrupting `[a,x,y,d,e,b,c]` instead of
`[a,x,y,b,c,d,e]`; the destination offset is `index + numNew`. `add(int,E)` delegates to
`insertElementAt` and `addAll(int, Collection)` is overridden because the inherited `AbstractList`
versions throw plain `IndexOutOfBoundsException`, while the JDK (and the test) compare
`ArrayIndexOutOfBoundsException` messages such as `"4 > 3"` and `"Array index out of range: 99"`.
