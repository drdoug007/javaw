# T54 CountDownLatch

Implemented: `java.util.concurrent.CountDownLatch` (field `int count`; `CountDownLatch(int)`, `await()`,
`countDown()`, `getCount()`, `toString()`) in the exception runtime, single-threaded contract. The constructor
throws `IllegalArgumentException("count < 0")` for negative counts; `countDown` stops at 0; `getCount` widens to
`long`; `await` returns at 0 and throws `IllegalStateException` for a positive count (would block forever);
`toString` is `super.toString() + "[Count = " + count + "]"` reading the field directly, with no overridable
self-calls.

Left out: `await(long, TimeUnit)` (test `leavesOutTimedAwait` requires it stays unlinked; `TimeUnit` exists in
the runtime since v315 but the timed await would have to sleep), the `Sync`/`AbstractQueuedSynchronizer`
machinery, `serialVersionUID`/`Serializable`, and `equals`/`hashCode` overrides (identity is inherited from
`Object`).

Notes: passed on the first check. The task file's prose says `TimeUnit` is "not in the runtime yet" — that is
stale (T52 linked it in v315) — but it does not change this task: the class simply does not define the timed
`await` overload, which is what the test verifies.
