# T56 Duration

Implemented: `java.time.DateTimeException` (two `RuntimeException` constructors), `java.time.format.DateTimeParseException`
(stores `parsedData.toString()` and `errorIndex`, `getParsedString`/`getErrorIndex`), and `java.time.Duration`
(core subset, `final`, `Comparable<Duration>, java.io.Serializable`) in the bundled exception runtime: the `ZERO`
constant with shared identity, all seven factories (`ofDays/ofHours/ofMinutes/ofSeconds/ofSeconds(long,long)/
ofMillis/ofNanos`) with floor-second normalisation and `multiplyExact`/`addExact` overflow, the seven `plus*`
variants with a private `plus(long,long)` (zero adjustment returns `this`, nanos carried into seconds), the seven
`minus*` variants (each handling a `Long.MIN_VALUE` argument as `plusX(MAX_VALUE).plusX(1)`), `multipliedBy` /
`dividedBy` (BigDecimal path, `RoundingMode.DOWN` truncation toward zero, `dividedBy(0)` ->
`ArithmeticException("Cannot divide by zero")`, out-of-range -> `ArithmeticException`), `negated` / `abs`, the six
`toX` conversions, `compareTo` / `equals` / `hashCode`, ISO-8601 `toString` (hours largest unit, no days, the
`effectiveTotalSecs++` and `-0` branches for negative-with-nanos, fraction from `nanos + 1_000_000_000` with
trailing zeros removed), and a hand-written `parse` (no `java.util.regex`) matching the JDK's
`DateTimeParseException` messages, errorIndex 0, and original-exception causes.

Left out: everything naming `java.time.temporal` (`of(long, TemporalUnit)`, `from`, `between`, `get`, `getUnits`,
`plus/minus(long, TemporalUnit)`, `addTo`/`subtractFrom`, `truncatedTo`; no `implements TemporalAmount` and no
`java/time/temporal` files), the Java 9+ extras (`dividedBy(Duration)`, `withSeconds`, `withNanos`, `toXxxPart`,
`isPositive`), and serialization internals (`writeReplace`, `readObject`, `writeExternal`, `readExternal`, `Ser`)
while keeping `implements java.io.Serializable`.

Notes: the first `kit check` failed `parsing` — the hand parser's hour/minute groups treated any digits after `T`
as their own group and rejected the text when the following letter did not match, so `PT15M` and `Pt1,5s`
(minutes-only / fraction-only) were wrongly rejected. The fix scans the digit run with a look-ahead index and
commits each group only when its terminating letter is present, letting `PT15M` fall through to the minutes group
and `Pt1,5s` to the seconds group; `kit check` then passed. `ofSeconds(-1, 1)` prints `PT-0.999999999S` and
`ofSeconds(60, 10)` prints `PT1M0.00000001S`, confirming the negative-fraction and fraction-writing branches.
