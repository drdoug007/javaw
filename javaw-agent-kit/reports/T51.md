# T51 LinkedBlockingQueue

Implemented: `java.util.concurrent.BlockingQueue` (the nine declared members) and
`java.util.concurrent.LinkedBlockingQueue` (Node, the three constructors, `size`, `remainingCapacity`,
`put`, `offer`, `poll`, `take`, `peek`, `remove(Object)`, `contains`, `toArray()`, `toArray(T[])`,
`toString`, `clear`, `drainTo(c)`, `drainTo(c, int)`, `iterator` and the `Itr` inner class with
`succ`/`findPred`) under the single-threaded contract: plain `int count`, sentinel head, real unlinking,
the JDK's `put`/`take` without `offer`/`poll`, `drainTo` with the `c == this` check before `max <= 0` and
the finally-based partial transfer, and the weakly consistent iterator that returns its already-fetched
item. `java.lang.InterruptedException` already existed and was registered by T49, so it was left
unchanged per the task.

Left out: timed `offer(E, long, TimeUnit)` / `poll(long, TimeUnit)` (needs `TimeUnit`, which is not in
the runtime yet), `writeObject`/`readObject`, `forEach`/`removeIf`/`removeAll`/`retainAll` overrides,
`spliterator`/`LBQSpliterator`, `Itr.forEachRemaining` and `bulkRemove`; the JDK's `ReentrantLock`/
`Condition`/`AtomicInteger`/`fullyLock` internals are replaced by the single-threaded contract, and a
`put` that would block forever throws `IllegalStateException` instead (never reached by the test).

Notes: the implementation follows the JDK 21 source (`src.zip` `java.base/java/util/concurrent/
LinkedBlockingQueue.java`) with the locks removed. The iterator's `succ` restarts at `head.next` when it
hits a self-linked (dequeued) node, which is what lets an iterator walk on past polled elements without
looping; `clear` self-links the old chain and resets `head = last` so the queue can be refilled. All
fixtures passed on the first `kit check`.
