# T79 java.nio.CharBuffer heap and CharSequence core

Implemented:
- `CharBuffer` (abstract, `Comparable<CharBuffer>, Appendable, CharSequence`; not `Readable`, not
  `Serializable`): the `allocate`/`wrap` factories; the abstract element/view members; the bulk `get(char[],
  int, int)`/`get(char[])`, `put(char[], int, int)`/`put(char[])`, `put(String, int, int)`/`put(String)` and
  `put(CharBuffer)` written once on top of the abstract `get(int)`/`put(int, char)`; the read-only-heap
  (`isReadOnly && hb != null`) checks in `put(CharBuffer)`, `put(String, int, int)` and both
  `append(CharSequence...)`; the `Appendable` members (no `throws`); `length`/`isEmpty`/`charAt`/`toString`
  relative to the position; `hasArray`/`array`/`arrayOffset` (string buffers throw
  `UnsupportedOperationException` before the read-only check); the seven covariant `Buffer`-returning overrides;
  the static `checkRange` helper (JDK `Objects.checkFromIndexSize` text); `hashCode`/`equals`/`compareTo`.
- `HeapCharBuffer` (package-private final): one class for writable and read-only heap buffers — `isReadOnly`,
  `order()`, `slice`/`duplicate`/`asReadOnlyBuffer`, relative and absolute `get`/`put`, `compact` (position
  rem, limit capacity, mark discarded), `subSequence` (position `pos + start`, limit `pos + end`, keeping
  capacity and offset; `Range [start, end) out of bounds for length n` message) and `toString(int, int)`.
- `StringCharBuffer` (package-private final): read-only live view of a `CharSequence` (`hb` null, reads
  `str.charAt(offset + i)` on every access), same view members, message-less `subSequence` exception, and
  unconditional `ReadOnlyBufferException` from `put(char)`, `put(int, char)` and `compact`.
- Registered all three classes with `kit register`; added `docs/bytecode-char-buffer.md`.

Left out: `Readable`/`read(CharBuffer)`, the JDK 13+ absolute bulk members (`slice(int, int)`,
`get(int, char[])` and friends, `put(int, ...)`), `mismatch`, direct buffers and `ByteBuffer.asCharBuffer()`
(all checked as unlinked by `leavesOutReadableAbsoluteBulkAndViews`).

Notes: passed on the first `kit check` attempt. The read-only ordering differs between the two classes and
matches the JDK's separate `HeapCharBufferR`/`StringCharBufferR`: a read-only heap buffer throws
`ReadOnlyBufferException` first (even for `put(itself)`), while a string buffer runs `src == this` and the range
checks first. `put(CharBuffer)` copies through a temporary `char[]`, so duplicates sharing one array with
overlapping ranges (tested in both directions) come out correct. The `chars()` fixtures linked the
`CharSequence`-default `IntStream` path (`CharacterStreams.chars`, `sum`/`count`/`filter`) for the first time;
admission handled it without changes.
