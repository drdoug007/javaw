# T37 EnumSet

Implemented: `java/util/EnumSet.java` — one concrete class over a `long[]` bit vector (one word per 64
constants, at least one) holding `final Class<E> elementType`, package-private `final Enum<?>[] universe` and
`private long[] elements`. Every public Java 17 factory: `noneOf` (`not an enum` message), `allOf`,
`copyOf(EnumSet)`, `copyOf(Collection)` (`Collection is empty` for other empty collections), `complementOf`,
`of(e)`..`of(e1..e5)`, the `@SafeVarargs of(first, rest...)` and `range` (`from > to` using `toString`), all
through `getDeclaringClass()` (never `getClass()`, so constants with bodies work). `clone()` (deep-copies the
bit array), package-private `typeCheck` (`eClass + " != " + elementType`) and private `fillAll`/`complement`
(last-word mask `-1L >>> -universe.length`, guarded for an empty enum)/`addRange`/`accepts`/`sameKind`.
`iterator()` is the JDK `JumboEnumSet` iterator copied exactly, in a non-static inner `Itr` that re-reads the
outer `elements` each step (word snapshot for ≤64 constants, later words read live). `size`/`isEmpty`/
`contains`/`add`/`remove`/`clear`, and the `Set` bulk operations (`containsAll`/`addAll`/`removeAll`/
`retainAll`) with the word fast path only between sets of the same kind, plus `equals` over
`Arrays.equals(elements)`. Registered via `kit register`.

Left out: serialization (`writeReplace`, `readObject`, `readObjectNoData`, nested `SerializationProxy`) — the
test checks `writeReplace()` stays unlinked. The JDK `RegularEnumSet`/`JumboEnumSet` subclasses are not created
(one concrete class instead, so `getClass()` differs; fixtures never print it). `hashCode`, `toString`,
`toArray`, `toArray(T[])` and `removeIf` are inherited from `AbstractSet`/`AbstractCollection`/`Collection` and
not overridden. `Class`, `Enum`, `AbstractSet`, `AbstractCollection` and all other runtime files untouched.

Notes: the check passed on the second run. The first run failed `wideUniverse` and `containsAllCases` for one
reason: I had the `containsAll` fast-path direction inverted (`elements[i] & ~es.elements[i]` instead of
`es.elements[i] & ~elements[i]`), which made `a.containsAll(r)` and `r.containsAll(a)` swap and made a
non-empty set report it does not contain an empty set. The rest (factories, element types, iteration,
equality/text/copies, `leavesOutSerialization`) passed first try.
