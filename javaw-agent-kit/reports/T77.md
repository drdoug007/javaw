# T77 CopyOnWriteArraySet

Implemented: `java.util.concurrent.CopyOnWriteArraySet` extending `AbstractSet` and implementing
`java.io.Serializable`, wrapping a `final CopyOnWriteArrayList<E> al`. All listed members delegate to the
list: `size`/`isEmpty`/`contains`/`toArray`/`toArray(a)`/`clear`/`remove`/`iterator`/`removeIf`/`forEach`/
`removeAll`/`retainAll` to the list's own methods; `add` to `al.addIfAbsent`; `addAll` to
`al.addAllAbsent(c) > 0`; `containsAll` to `compareSets(al.getArray(), c) >= 0` for a `Set` argument and
`al.containsAll(c)` otherwise; `equals` to `o == this || (o instanceof Set && compareSets(...) == 0)`. The
private static `compareSets` is copied from the JDK exactly (matched[]/j algorithm, no `set.size()` call).
The Collection constructor copies `cc.al` only when `c.getClass() == CopyOnWriteArraySet.class` (exact class),
else `al.addAllAbsent(c)`. Registered with `kit register`; `docs/bytecode-copy-on-write-array-set.md` created.

Left out: `spliterator()` (inherited `Set` default), `hashCode()` and `toString()` (inherited from
`AbstractSet`/`AbstractCollection` via `iterator()`, matching the JVM, including the `Spy`-observed
`iterator` calls), serialization methods (none in the JDK class; `al` is serialized).

Notes: first `kit check` passed with no failures. The two `equals`-log-sensitive paths differ by design:
the Set path of `containsAll`/`equals` uses `Objects.equals(x, snapshot[i])` (`==` first, so the test's
`Key("never")` does not log a self-match) while the non-Set path goes through
`CopyOnWriteArrayList.indexOfRange` (`o.equals(element)`, no `==` shortcut), and the test's `Key.log` pins
both call orders.
