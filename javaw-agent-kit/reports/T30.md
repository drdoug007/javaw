# T30 AtomicReferenceArray update and accumulate retries

Implemented: retry loops in the four existing `AtomicReferenceArray` methods `getAndUpdate`,
`updateAndGet`, `getAndAccumulate` and `accumulateAndGet`. Each now reads the element with
`get(index)` before calling the function, then loops: apply the function (accumulate passes
`(current element, x)`), `compareAndSet(index, prev, next)` by identity, return `prev` for the
`getAnd*` forms and `next` for the `*AndGet` forms, and re-read the element on a failed compare.
This is the same loop the T28/T29 runtimes use, with an extra `index` argument. Updated
`docs/bytecode-atomic-reference-array.md` (identity-compare sentence, new revision contract
bullet, callback-exception wording, evidence sentence).

Left out: nothing — no members added, removed or renamed; the class and `toString` stay
non-final for the test subclass.

Notes: first version passed `kit check` on the first run. Identity, not `equals`, is what
drives the retry: storing an equal-but-different reference (or a nested update of the same
index) re-calls the function, while restoring the same reference or touching other indexes
stores after one call. A function's own stores from earlier calls remain after its exception
propagates, and the index bounds check happens before the function is invoked.
