# T69 java.time.Period

Implemented: `java/time/Period.java` — core subset: shared `ZERO`; `of`/`ofYears`/`ofMonths`/`ofWeeks`/
`ofDays`; `parse(CharSequence)` (hand-written, JDK `DateTimeParseException` messages, parsed string, error
index and cause class); getters; `isZero`/`isNegative`; `withYears/withMonths/withDays`;
`plusYears/plusMonths/plusDays`/`minusYears/minusMonths/minusDays` (exact int arithmetic via long);
`multipliedBy`/`negated`/`normalized`/`toTotalMonths`; `equals`/`hashCode` (JDK rotate-left formula)/
`toString`; `implements java.io.Serializable`. Registered with `kit register`.

Left out: `TemporalAmount`/`ChronoPeriod` interfaces and everything naming types not in the runtime
(`between`, `from`, `get`, `getUnits`, `getChronology`, `addTo`, `subtractFrom`, `plus/minus(TemporalAmount)`),
serialization proxy (`writeReplace`/`readObject`/`Ser`).

Notes: `parse` overflow behaviour has three distinct shapes and the JDK's `parseNumber` wraps only the
leading-sign `multiplyExact` — the weeks*7/days `addExact` line throws a bare `ArithmeticException`. Verified
against the JDK 21 source before writing. All five `@Test` methods passed on the first `kit check`.
