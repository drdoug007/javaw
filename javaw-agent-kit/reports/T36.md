# T36 PrintStream

Implemented: `java/io/PrintStream.java` — the four `OutputStream` constructors (with the `Null output
stream`/`charsetName`/`charset` failures and `UnsupportedEncodingException` for bad names), `flush`, `close`,
`checkError`, `setError`, `clearError`, `write(int)`, `write(byte[], int, int)`, `write(byte[])`,
`writeBytes`, the nine `print` and nine `println` overloads plus `println()`, `printf`/`format` (plain and
`Locale`), the three `Appendable` methods, and the private `encode`/`emit` encoder (held high surrogate,
single UTF-16 byte order mark), `writeText`/`writeLine`/`newLine`, `ensureOpen`, `requireNonNull`,
`toCharset`. Registered via `kit register`.

Left out: the `File`/`String fileName` constructors (no `File`/`FileOutputStream` in the runtime; the test
checks `PrintStream(String)` stays unlinked), `charset()` (Java 18), the `lock`/`formatter`/`textOut`/
`charOut` fields, `SharedSecrets` static block, and `InterruptedIOException` handling (no threads).
`System.out`/`System.err` are not touched.

Notes: the check passed on the first run. Two subtleties from the task spec that were easy to get wrong:
`close()` calls the overridable `flush()` and `close()` (not `out.flush()`) before `out.close()`, so a
subclass logs `cl;fl;cl;`, and `println(x)` on a plain `PrintStream` must write `x` and `"\n"` in one
`write(byte[], 0, n)` call while subclasses get `print(x)` plus a separate `newLine()` — hence the
`getClass() == PrintStream.class` test (not `instanceof`).
