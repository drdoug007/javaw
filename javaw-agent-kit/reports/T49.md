# T49 Lock and ReentrantLock
Implemented: `java.util.concurrent.locks.Lock` (lock, lockInterruptibly, tryLock, unlock),
`ReentrantLock` (both constructors, the four Lock methods, getHoldCount, isHeldByCurrentThread,
isLocked, final isFair, toString), `java.lang.IllegalMonitorStateException` and
`java.lang.InterruptedException` (no-arg and String constructors). Single-threaded contract: one plain
`holds` count, `tryLock()` always true, `unlock()` with no hold throws `IllegalMonitorStateException`.
Left out: `newCondition`/`Condition`, `tryLock(long, TimeUnit)`, all queue/waiter inspection methods, and the
JDK `Sync`/`FairSync`/`NonfairSync`/`AbstractQueuedSynchronizer` machinery (all need `Thread`, `Condition` or
`TimeUnit`, which are not in the runtime). `equals`/`hashCode` not overridden.
Notes: `lock`/`tryLock`/`lockInterruptibly` each increment `holds` directly (no mutual calls, verified by the
callPattern log); `toString` uses `super.toString()` plus the `[Unlocked]`/`[Locked by thread main]` suffix
and reads `holds` directly. Check passed on the first attempt.
