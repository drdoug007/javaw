# T72 ThreadLocal and InheritableThreadLocal

Implemented: `java/lang/ThreadLocal.java` (`present`/`value` slot, `ThreadLocal()`, `initialValue()`,
`withInitial(Supplier)`, `get()`, private `setInitialValue()`, `set(T)`, `remove()`, and the static final nested
`SuppliedThreadLocal<T>` with a `requireNonNull`'d supplier) and
`java/lang/InheritableThreadLocal.java` (`InheritableThreadLocal()`, `childValue(T)` returning the parent value).
Registered both with `kit register`.

Left out: `java.lang.Thread`, `ThreadLocalMap`, `getMap(Thread)`, `createMap`, `createInheritedMap`,
`threadLocalHashCode`, `nextHashCode()`, `HASH_INCREMENT`, `isPresent`/`isCarrierThreadLocal` and the
virtual-thread/carrier variants — no `Thread` class exists in the runtime and none is created; `childValue` is
kept for subclasses but never called because no child thread is ever created; no `toString`/`equals`/`hashCode`
overrides (JDK uses `Object`'s).

Notes: The JDK stores the `initialValue()` result directly (via its private `setInitialValue`) rather than
calling `this.set(v)`; the `Spy` fixture's `set:` log confirmed the direct store was needed. `set(null)` needed
the separate `present` flag so a stored null does not retrigger `initialValue()` while `remove()` re-arms it.
PASS on the first `kit check` attempt.
