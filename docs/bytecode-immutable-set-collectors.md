# Immutable set collection

Revision `immutable-set-collectors-v75` adds Collectors.toUnmodifiableSet. It collects into a mutable set, merges duplicate values, and returns a defensive null-rejecting immutable snapshot. UNORDERED is retained; IDENTITY_FINISH is absent. Null rejection occurs in the finisher, including when supplier/accumulator are called directly. Iterators and all mutation paths remain protected. No iteration order, duplicate representative identity, parallel execution or concurrent collection is promised.

`BytecodeImmutableSetCollectorsTest` compares complete stream collection and direct supplier/accumulator/combiner/finisher use against the JVM. It checks duplicates, empty sets, characteristics, post-finish accumulator mutation, null finish failures and protected iterator/mutation paths, in both JAR orders and independent Wasm instances.

Pinned-library evidence uses the original Spring Beans 6.1.5 YamlProcessor.setSupportedTypes method and original Spring Core ObjectUtils.isEmpty(Object[]) and Assert.noNullElements(Object[],String) methods, after verifying both JAR hashes. The YamlProcessor carrier retains its supportedTypes field and original method body (Class::getName, Arrays.stream, map, toUnmodifiableSet, collect), exposes the field, removes unrelated abstract declarations and uses a synthetic trivial constructor. Tests cover duplicate/Class/array type names, immutable output, previous-result isolation, null/empty input and null-element failures. This proves selected original method linkage and execution; it excludes the original processor constructor, logging, YAML parsing and full Spring initialization.
