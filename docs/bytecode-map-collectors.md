# Sequential map collectors

Revision `map-collectors-v74` supplies all Java 17 `Collectors.toMap` and `toUnmodifiableMap` overloads in the bundled bytecode runtime. Accumulators and combiners reject null values, preserve nullable keys for mutable maps, and reject duplicate keys in the non-merging overloads. Merge callbacks support replacement and null-result deletion. The four-argument overload preserves the supplied map implementation and encounter insertion order. Mutable collectors have IDENTITY_FINISH; immutable collectors remove it and finish with a defensive Map.copyOf snapshot, rejecting null keys and closing entry mutation paths.

Ordinary toMap defers null mapper/merger/supplier failures until the relevant callbacks run; an empty collection can succeed with unused null mappers. toUnmodifiableMap eagerly validates its callbacks. Null callback failures, callback identity and stream single-use state are tested. Duplicate exception types are guaranteed; exact messages, map iteration order without an ordered factory, parallel execution and concurrent collectors are not.

`BytecodeMapCollectorsTest` compares accumulator, explicit combiner, finisher, duplicate/null handling, null-result merges, supplied LinkedHashMap order, characteristics, immutable snapshots and mutation failures with JVM execution in both JAR orders and independent instances.

The test also extracts the unchanged original Hibernate Core 6.4.4.Final Index constructor, getColumnOrderMap and its lambda helper, with the original no-argument Column constructor. The pinned JAR hash is verified. Only fields needed by these selected methods are retained; unrelated interfaces/methods are removed, and the input map field is exposed to the fixture. Column equality/hash methods are excluded, so this fixture uses identity keys. The original Index stream/toUnmodifiableMap call and lambda bytecode execute unchanged with nonempty/empty maps, null keys/values, immutable-result checks and snapshot isolation. This is selected-method evidence, not full Index/Column or Hibernate bootstrap, and uses no source facade for the collector call.
