# Legacy byte text construction and Jackson floating formatting

Revision `legacy-byte-text-v73` adds `String(byte[],int)` and `String(byte[],int,int,int)`. The highByte parameter contributes its low eight bits to each resulting UTF-16 code unit; source bytes contribute unsigned low eight bits. This is the deprecated JDK construction contract, not charset decoding. Results are defensive snapshots, slices are checked without integer-overflow arithmetic, and null/invalid slices raise Java exceptions. Charset/default-encoding constructors and getBytes remain open.

`BytecodeLegacyByteTextTest` compares all byte values, high-byte masking, slice extrema, nulls and snapshots against the JVM. It also executes the unchanged hash-verified Jackson Core 2.15.4 DoubleToDecimal, FloatToDecimal and MathUtils class files. Complete formatter bodies and original table initialization run in both JAR orders and independent Wasm instances. Each precision covers signed zeros, finite extrema, subnormal boundaries, infinities/NaNs and 600 deterministic raw floating patterns. Exact library-output hashes are compared with the same library on the JVM; JDK toString spelling is not substituted for Jackson's algorithm.

Formatting fixtures use the existing small imported-memory limit. They do not reparse every generated value in the same instance: a bump-only test allocator exhausted that limit when formatting and BigInteger-based reparsing were combined. Floating parsing has its separate executable regressions. This evidence establishes these formatter utility classes, not the Jackson JSON parser, serializer or full dependency closure, and makes no sustained-allocation/reclamation claim.
