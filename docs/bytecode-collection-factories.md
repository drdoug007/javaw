# Bytecode collection factories and read-only views

Revision `collection-factories-v67` adds bundled binary implementations of List.of, Set.of and Map.of (all fixed arities and varargs forms), List/Set/Map.copyOf, Map.entry and Map.ofEntries. Factories make defensive snapshots, reject null elements/keys/values, and reject duplicate set elements/map keys where specified. Set.copyOf deduplicates its source. Immutable map entries and all mutation entry points are protected. Iteration order of these immutable factories is unspecified; no JDK implementation class identity or serialization representation is promised.

Collections adds empty/singleton maps and sets, EMPTY_LIST/SET/MAP, nCopies, unmodifiableCollection/List/Set/Map, empty iterators/enumerations, enumeration/list conversion and newSetFromMap. Read-only wrappers are live views: backing changes remain visible, backed iterators retain their fail-fast behavior, sublists remain backed, and list RandomAccess markers are retained. Map entries are protected through iterators, callbacks and both array export forms. Callback and default mutation methods reject changes even when the operation could otherwise be a no-op. Empty and singleton factories have their own JDK mutation behavior rather than inheriting all unmodifiable-wrapper behavior.

Internal typed-array allocation is part of the binary contract. Reflection/array adapter discovery now follows referenced bundled methods, including method handles in lambda bootstrap arguments, and conservatively follows virtual overrides within the declared receiver hierarchy. Thus Map.copyOf's internal entry-array export works even when the application has no direct toArray or reflection call. This traversal chooses adapter generation; it does not establish whole-program dependency reachability or make absent JDK methods supported.

`BytecodeCollectionFactoriesTest` executes javac-generated bytecode against JVM and Wasm in both JAR orders and independent module instances. It covers input isolation, null/duplicate failures, unmodifiable entry exports, live views, nested sublists, iterator invalidation, default mutation guards, empty/singleton distinctions, enumerations, map-backed sets and Map::copyOf's hidden allocation path.

The real-library fixture executes the entire unchanged pinned Logback Core 1.4.14 `ch.qos.logback.core.joran.util.beans.BeanDescription` class, whose constructor wraps getter/setter/adder maps. The artifact SHA-256 is `f8c2f05f42530b1852739507c1792f0080167850ed8f396444c6913d6617a293`. The fixture verifies live backing updates and protected entries. This proves that selected class's behavior, not Logback startup or the logging pipeline.

Synchronized wrappers, sorted/navigable maps and sets, additional collection implementations, primitive streams and the closure-wide core JDK execution gate remain open. These wrappers introduce no concurrency or memory reclamation guarantees.
