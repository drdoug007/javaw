# Bundled floating parsing and wrapper values

Revision `floating-values-v66` adds ordinary bytecode-backed Double/Float string constructors, valueOf(String), parseDouble/parseFloat, static and instance isInfinite, static isFinite, sum/min/max, plus Boolean string construction/valueOf/parseBoolean and logical reductions. These operate in Wasm within the isolated exception runtime, independently of the source compiler's facades.

Floating parsing accepts ASCII Java decimal and hexadecimal floating syntax, optional leading signs, signed exponents, decimal points, f/F/d/D suffixes, NaN and Infinity. Leading/trailing characters at or below U+0020 are trimmed. Hexadecimal inputs require a binary p/P exponent. Decimal and hex significands require at least one digit; underscores, Unicode digits, extra characters and malformed exponents fail with NumberFormatException. Null input fails with NullPointerException. Boolean parsing follows its separate contract: null and all strings other than a case-insensitive `true` return false, without trimming.

Decimal parsing constructs an exact coefficient/scale and uses BigDecimal's direct rational-to-IEEE rounding. Hex parsing rounds the binary integer significand directly to the requested precision. Float parsing does not round through double. Both preserve signed zero, round ties to even, support subnormals and saturate overflow/underflow to signed infinity/zero. Exponent accumulation saturates only after a bound exceeding any in-memory input's compensating scale, while still validating every character. Exact specials bypass numeric construction. NaN payloads and exception-message text are not promised. Large significands remain bounded by available Wasm memory; no JDK performance or managed reclamation claim is made.

`BytecodeFloatingValuesTest` compares javac fixtures with JVM execution, then executes Wasm with both JAR orders and independent instances under the default memory limit. Four tests cover decimal/hex grammar, trim controls, suffixes, wrappers and finite checks, exponent extremes, signed zero, exact half-way values, float double-rounding traps, normal/subnormal and maximum-finite boundaries, malformed inputs and typed null failures.

The H2 2.2.224 artifact hash is verified (`b9d8f19358ada82a4f6eb5b174c6cfe320a375b5a9cb5a4fe456d623e6e55497`). The complete original private static `MathFunction.roundMagic(double)` instructions execute in an isolated public static-method carrier. Only the carrier class and access flag change; the method body is retained. Inputs exercise early returns and the StringBuilder mutation/Double.parseDouble path. The JVM oracle executes that same retained body. This is selected-method evidence, not the surrounding expression hierarchy, SQL dispatch or H2 startup.

Remaining core work includes Unicode/case and other String APIs, remaining audited numeric methods, collection families/wrappers, primitive streams/spliterators, broader collectors and the closure-wide reachability gate. Property lookup for Boolean.getBoolean belongs to the selected host/property contract and is not introduced here.
